# AI导购预算执行与审计参考实现

本目录只落实复审第三项。规则来自报告既有责任判准，原六臂统计、规范论证与创新定位保持原文。

## 可执行入口

```text
python governance/check_protocol.py
```

此命令使用Python标准库，运行16项明确标注为构造输入的工程断言，写入protocol_results.json。它检查预算授权、提示去重、停止与筛选约束，不产生消费者反应、心理效应或自主性总分。

budget_guard.py把生效预算与条件预览分开管理。理由撤回不会自动回滚预算；实际更新需对应明确用户表达。audit_events是分离的日志检查函数，可检查无授权改写和超上限筛选。金额使用整数分，避免浮点金额误差。独立检查组件不等于外部独立人类评审。

已有事件JSON可从仓库根目录检查：

```text
python governance/budget_guard.py trace.json --initial-budget-cents 20000
```

用户授权原话和角色必须来自可信会话记录。程序不识别真实心理因果，也不保证上游传入的原话或来源为真；部署前需接入会话、商品到手总价、权限和纠错接口。当前实现处理明确授权路径；预先委托在实际系统中还需可核范围和撤回机制，不能将布尔字段当作授权凭证。

## 触发与停止

rules.json保存报告表4的九项规则。重要依据变化、公开预算联系、可调整性、实际缺口与相称负担共同决定是否主动提示。仅凭点击、停留或提价不得建立关联。

同一实质依据版本默认至多一次主动预算邀请，普通更正充分时零次。该次数是本实现配置，不是经验证的伦理最优值。用户主动追问单独处理；换措辞不重置计数，新实质事实须有可靠来源。知情重申的记录指向先前告知及后续原话，不替代真实理解测量。

负担分别记录提示次数、字符、额外步骤、完成时间及可选自报。当前没有用这些构造输入估计真实负担，也没有设置实证验证的负担阈值。关闭商业推动与必要纠错通知分别处理，纠错不能自动恢复营销。

## 文件

- budget_guard.py：预算状态守卫与事件日志检查。
- check_protocol.py及protocol_results.json：16项工程断言及实际执行记录。
- rules.json：与报告表4对应的触发、措施、验收、停止规则。
- [伦理审计清单](伦理审计清单.md)：按G1—G9分别记录符合、不符合、记录不足或不适用，列明责任主体、记录字段与实施代价。
- build_submission_report.py：只修改第四章及材料附录的Word包补丁，保护前三章、摘要、结论和参考文献。
- build_defense.mjs：配套PPTX生成源码，使用Codex bundled @oai/artifact-tool；需要TASK_WORKSPACE、PRESENTATIONS_SKILL_DIR、RUNTIME_PYTHON等环境路径，实际成品在submission。
- verify_submission.py：报告、PPT、匿名包及原分析保护范围的核对程序。

这些是治理设计与工程验收材料。原数据与原分析继续由research/domestic_data_reanalysis_20261029管理。

## 2026-10-30边界复核与最小修复

原16项检查继续保留；新增边界检查从任意目录运行：

```text
python governance/check_boundaries.py
```

新实质事实默认不获认可，withdraw必须显式传material_change=True，并提供稳定的理由ID和不可变事实版本定位source_ref。同一理由及同一source_ref不能靠更换revision重开提醒；内容真实更新即使沿用相同网页地址，也应提供内容版本或摘要哈希定位。该接口要求可信接入层完成语义复核，程序不能辨别伪造的新来源。

预算授权的user_turn在一个任务内只能消费一次，审计器同时检查authorization_event和原话是否重复使用或缺失。结束会关闭营销并拒绝同任务的普通预算更新与筛选；用户再次主动开启协助应建立另一个清楚标记的任务上下文，不能静默恢复旧营销。

reaffirm新增after_notice_reviewed=False的默认值，接入层核对原会话中表达晚于告知后，才能显式设为True。这个标记记录复核责任，不证明源会话真实性或心理理解。关联原话、事实来源与判定字段、提示内容及重申原话写入事件，供受控导出；实际部署仍需最小留存、权限及删除安排。

修复前后使用相同探针的记录位于review_20261030。它们与原消费者数据和16项基础断言分开管理。本轮新增代码只处理应用承诺，不改伦理前提或原统计解释。

build_anonymous_package.py可重建匿名ZIP；四个历史链接位置使用明示导航页，不修改原research文件。verify_submission.py仅供完整仓库核对，匿名子集使用自身SHA256SUMS.json及相对导航。
